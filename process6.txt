Issue #24: Frontend - Central Error Handling & API Resilience (Bonus/Stabilization)

Problem Summary:
Frontend projesinde yer alan tüm dışa veya içe dönük API isteklerinin; yetkisizlik (401), yasaklı erişim (403), sunucu çökmesi (500) veya veri bulunamaması (404) gibi hataları sessizce yutmasını engellemek. Tüm hataları merkezi bir noktada yakalayarak kullanıcıyı bilgilendiren Interceptor yapısı inşa etmek.

Scope:
Frontend (Axios/Fetch Configuration & Error State Management).

Deliverables:
Axios/Fetch Global Request & Response Interceptor config dosyası.

Uygulama genelinde gösterilecek global hata sayfası/durumu (Örn: 403 Access Denied bileşeni).

References:
Core Architecture

Acceptance Criteria:
[ ] Backend servisi JWT token veya yetki hatası yüzünden 401 Unauthorized dönerse, interceptor bu hatayı yakalamalı ve kullanıcıyı zorunlu olarak Login/Giriş sayfasına yönlendirmeli.

[ ] Backend 500 hatası döndüğünde uygulamanın beyaz ekrana (White screen of death) düşmesi engellenmeli, interceptor vasıtasıyla ekranda Issue #20 üzerinden "Sunucu Hatası Oluştu" şeklinde global Toast gösterilmeli.

[ ] (Örnek: GET /active-sprint 404 dönerse) uygulamanın ilgili modüllerinde "Aktif Sprint Bulunamadı" şeklinde Empty State bileşenlerinin tetiklenmesi garanti altına alınmalı.

Related Issues:
#Tüm Frontend APı İstekleri, #20 Frontend - Global Toast Notification System
